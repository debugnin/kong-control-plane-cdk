This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

AWS CDK (TypeScript) project that deploys a self-hosted **Kong Gateway Enterprise control plane** on ECS Fargate, backed by **Aurora Serverless v2 (PostgreSQL)** and protected by **AWS Backup**. It contains no data plane code; data planes are deployed elsewhere and connect to the NLB on 8005/8006. Refactored from `konnect-ecs-dataplane`.

## Commands

```bash
npm run build        # Compile TypeScript
npm test             # Jest (CDK assertions) - run after any change to lib/
npx cdk synth        # Generate CloudFormation templates
npx cdk diff
npx cdk deploy --all # network -> database -> service
```

Synth needs `ENVIRONMENT` plus the required config (see README). Leave `CDK_DEFAULT_ACCOUNT` unset for local synth to avoid AZ lookups needing credentials:

```bash
ENVIRONMENT=dev KONG_IMAGE_URI=kong/kong-gateway:3.15 \
  KONG_LICENSE_SECRET_ARN=arn:aws:secretsmanager:ap-southeast-2:123456789012:secret:l-AbCdEf \
  CLUSTER_CERT_SECRET_ARN=arn:aws:secretsmanager:ap-southeast-2:123456789012:secret:c-AbCdEf \
  ALB_CERTIFICATE_ARN=arn:aws:acm:ap-southeast-2:123456789012:certificate/x npx cdk synth
```

## Architecture

Entry point `bin/kong-cp-cdk.ts` reads config and creates three stacks in dependency order:

- **`KongNetworkStack`** (`lib/kong-network-stack.ts`) - `VpcConstruct`
- **`KongDatabaseStack`** (`lib/kong-database-stack.ts`) - `AuroraConstruct`, `BackupConstruct`, generated admin + session secrets. Stateful; termination protection follows `dbDeletionProtection`.
- **`KongControlPlaneStack`** (`lib/kong-control-plane-stack.ts`) - ECS Fargate service (`kong-migrations` init container + `kong-cp`), internal ALB (`AlbConstruct`; 443 Manager, 8444 Admin API), internal NLB (8005/8006 TCP), `CertificateConstruct`, `WafConstruct`, `LoggingConstruct`

Constructs live in `lib/constructs/`.

## Configuration Precedence

1. `config/{environment}.json` (highest) - see `config/dev.json.example`
2. `cdk.context.json` / `--context`
3. Environment variables (lowest)

Helpers `str/num/bool/list/required` in `bin/kong-cp-cdk.ts` read keys; add new settings there and document them in the README tables.

## Key Design Decisions

- **Stateful/stateless split:** database + backup are in their own stack so the service can be replaced safely.
- **No cross-stack grants on the DB KMS key:** the service stack imports the Aurora secret by ARN and the key by ARN (`Secret.fromSecretAttributes`). Passing the `Secret` object across stacks makes CDK add a key-policy grant in the database stack and creates a dependency cycle. The Aurora security group ingress for the tasks is a `CfnSecurityGroupIngress` in the service stack for the same reason.
- **Migrations:** `kong migrations bootstrap` runs as a non-essential init container on every task start (idempotent). Upgrades (`up`/`finish`) are manual - see docs/DEPLOYMENT_GUIDE.md.
- **Health checks** use the Status API (`KONG_STATUS_LISTEN` 8100, `/status`), which is not subject to RBAC. RBAC and Manager basic-auth are enabled (`KONG_ENFORCE_RBAC=on`).
- **Aurora TLS is verified.** Kong's global `tls_certificate_verify` rejects `KONG_PG_SSL_VERIFY=off`; the regional RDS CA bundle (`certs/rds-ca-{region}.pem`, `scripts/fetch-rds-ca.sh`) is passed as base64 content in `KONG_LUA_SSL_TRUSTED_CERTIFICATE`. ECS `run-task` container overrides are capped at 8 KB, so test changes to this variable on one container only.
- **Cluster mTLS** is `shared` mode; cert/key come from a user-supplied secret (`scripts/create-cp-secrets.sh`).
- **Internal by default:** ALB and NLB are internal; `albInternetFacing` exists but should stay `false`.
- **Backup:** AWS Backup daily rule always on; weekly/monthly are opt-in (`0` disables); optional cross-region copy via `backupCopyToVaultArn`. Restore via `dbSnapshotIdentifier` (replaces the cluster on an existing stack).
- **Aurora min capacity is 0.5 ACU** (not scale-to-zero): Kong keeps persistent connections.
- **One environment per account/region** - resource names are fixed per `environment` (see docs/NAMING_CONVENTIONS.md).

## Secrets

| Secret | Created by |
|---|---|
| `kong/cp/{env}/db-master` | Stack (generated by Aurora) |
| `kong/cp/{env}/admin` (`password`) | Stack (generated) |
| `kong/cp/{env}/manager-session` (JSON for `KONG_ADMIN_GUI_SESSION_CONF`) | Stack (generated) |
| `kong/cp/{env}/license` | `scripts/create-cp-secrets.sh` (value = license JSON) |
| `kong/cp/{env}/cluster-cert` (`cluster_cert`, `cluster_cert_key`) | `scripts/create-cp-secrets.sh` |

## Testing

`test/kong-cp.test.ts` uses CDK assertions: Aurora serverless v2 config, AWS Backup plan/rules, service environment, migrations ordering, internal ALB / NLB listeners, snapshot restore. Extend it when changing constructs.
