# Scripts

## `create-cp-secrets.sh`

Creates the two Secrets Manager secrets the stack consumes but cannot generate.

```bash
./scripts/create-cp-secrets.sh <env> <license.json> [region]
```

| Secret | Contents |
|---|---|
| `kong/cp/{env}/license` | The Kong Enterprise license file, verbatim |
| `kong/cp/{env}/cluster-cert` | JSON `{"cluster_cert": "<PEM>", "cluster_cert_key": "<PEM>"}` – a self-signed EC (secp384r1) certificate, CN `kong_clustering`, valid 3 years |

- Requires `aws`, `openssl`, `jq` and permission for `secretsmanager:CreateSecret`/`DescribeSecret`.
- Idempotent: an existing secret is never overwritten.
- Prints the ARNs to paste into `config/{env}.json` (`kongLicenseSecretArn`, `clusterCertSecretArn`).
- The same certificate/key must be used by every data plane (`cluster_mtls=shared`). Replace it with a certificate from your own PKI if your security policy requires it – just keep the two key names.
- The private key is generated in a temp directory that is removed on exit.

Generated by the stack (no script needed): Aurora master credentials, Kong super-admin password (`kong/cp/{env}/admin`) and the Manager session secret.

## `fetch-rds-ca.sh`

```bash
./scripts/fetch-rds-ca.sh <region>     # e.g. ap-southeast-2
```

Downloads the regional Amazon RDS CA bundle to `certs/rds-ca-<region>.pem`. The stack embeds it (base64) in `KONG_LUA_SSL_TRUSTED_CERTIFICATE` so Kong can verify the Aurora server certificate without a custom image. The bundle is public and committed; re-run the script when AWS rotates the RDS CA.
